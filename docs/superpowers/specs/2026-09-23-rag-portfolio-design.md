# RAG LAB 개인 포트폴리오 MVP

## 목적과 범위

기존 채팅 화면을 개인 문서 기반 RAG 데모로 완성하고 Vercel의 단일 도메인에 배포한다. 방문자는 화면을 볼 수 있지만 API 호출에는 소유자가 공유한 접근 코드가 필요하다. 이 버전은 다중 사용자 계정과 사용자별 문서 분리를 제공하지 않는다.

## 선택한 구조

Vite 프론트엔드와 FastAPI API를 한 Vercel 프로젝트에 둔다. OpenAI 관리형 벡터 저장소 하나가 업로드한 문서의 청킹, 임베딩, 색인을 맡는다. Vercel 함수 파일 시스템에 영구 데이터를 저장하지 않는다. 벡터 저장소 ID는 서버 환경 변수로 고정한다.

자체 청킹 및 별도 벡터 DB는 커스터마이징 여지가 크지만 배포와 운영 요소가 늘어난다. OpenAI File Search만 모델에 맡기는 방식은 간단하지만 검색 근거와 답변 스트림을 프론트엔드에 명시적으로 전달하기가 어렵다. 따라서 검색 API로 근거를 먼저 얻고, 기존 채팅 모델에 검색 문맥을 전달해 답변을 스트리밍한다.

## 기능

1. 접근 코드: 모든 API 요청은 서버의 `APP_ACCESS_CODE`와 비교한다. 프론트엔드는 코드를 현재 브라우저 세션에만 저장한다. 미설정 서버는 API 요청을 거부한다.
2. 문서: 소유자는 PDF, TXT, Markdown 파일을 최대 4MB까지 업로드한다. API는 확장자, 크기, 비어 있는 파일을 검증한다. OpenAI Files와 벡터 저장소에 등록하고 색인 상태를 제공한다. 목록 및 삭제를 제공한다.
3. 질문: 준비된 문서가 없으면 답변 생성 대신 안내한다. 서버가 질문으로 벡터 저장소를 검색한 후 상위 결과를 번호 붙인 근거로 모델에 준다. 근거 없는 내용은 모른다고 답하도록 지시한다.
4. 응답: 서버는 SSE로 검색 근거, 텍스트 조각, 완료 또는 오류를 보낸다. 프론트엔드는 기존 중단 버튼과 마크다운 렌더링을 유지하고 근거 문서명을 답변 아래에 표시한다.
5. 배포: 루트 Vercel 설정이 `frontend`를 빌드하고 Python `api/index.py`를 함수로 배포한다. `OPENAI_API_KEY`, `OPENAI_VECTOR_STORE_ID`, `APP_ACCESS_CODE`는 Vercel 서버 환경 변수이며 Git에 넣지 않는다.

## 오류와 경계

업로드 또는 색인 실패는 문서 상태로 노출한다. 검색 및 생성 실패는 SSE 오류 이벤트로 전송한다. 비정상 접근 코드는 401, 서버 설정 누락은 503이다. 문서 텍스트는 신뢰할 수 없는 검색 자료로 취급해 모델의 상위 지시를 덮어쓰지 못하도록 한다. OpenAI 비용과 무단 호출을 제한하기 위해 접근 코드를 모든 데이터 API에 요구한다.

## 검증

백엔드 단위 테스트에서 인증, 업로드 검증, 검색 근거, 스트리밍 이벤트를 확인한다. 프론트엔드 테스트에서 접근 코드, 업로드, 근거 표시를 확인한다. 타입 검사, 린트, 빌드를 통과시킨다. 로컬 브라우저에서 데스크톱 및 모바일 입력·업로드 흐름을 검증하고, 배포 후 실제 API 경로와 응답을 확인한다.
